# Frontend — Security Dashboard

Le dashboard doit afficher le contexte et les actions permises par l'API, mais ne constitue pas une frontière de sécurité. Masquer un bouton ne remplace jamais le contrôle d'autorisation côté serveur.

Écrans fonctionnels à construire :

1. Inventaire des actifs et statut de leur autorisation de test.
2. Findings, sévérité technique, confiance, statut et remédiation.
3. Incidents, chronologie, événements associés et playbooks proposés.
4. File d'approbation des actions sensibles et historique d'audit.
5. État des connecteurs et contrôles DevSecOps.

Stack suggérée : React + TypeScript ; à valider dans un ADR avant de générer la chaîne de build.
